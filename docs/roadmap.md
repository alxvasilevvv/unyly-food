# Блокеры реального запуска и план следующей версии

## Блокеры

### Для реальных заказов GrabFood (Live)
| # | Блокер | Кто снимает | Что нужно |
|---|---|---|---|
| B1 | Нет API для заказа от имени покупателя (поиск, меню, цена, создание заказа) | Grab (BD / partnerships) | Партнёрское соглашение и документация consumer-ordering или affiliate API |
| B2 | Нет scope GrabID для заказов и оплаты от имени пользователя | Команда GrabID | Список scopes, регистрация redirect URI, условия |
| B3 | Нет схемы оплаты заказа (GrabPay в контексте GrabFood) | Grab | Модель оплаты: оплата в Grab с редиректом или токенизация |
| B4 | Нет документированной подписи webhook и статусов потребительского заказа | Grab | Спецификация событий и схема подписи |
| B5 | Нет гарантий идемпотентности создания заказа | Grab | Поле idempotency key или поиск заказа по нашему ключу. Без этого нельзя безопасно сверять неизвестные исходы |
| B6 | Юридическое: PDPA Таиланда, оферта, ответственность за заказ, возвраты | Юрист | Политика данных, оферта, DPA с Grab |

Черновик обращения к Grab - `grab-partner-request.md` (**не отправлен**).

### Для публикации Demo и Handoff (решается за день)
| # | Блокер | Что нужно |
|---|---|---|
| P1 | `unyly.org` занят действующим продуктом «MCP Server Marketplace» | Решение владельца: отдельный хост, например `food.unyly.org` |
| P2 | Нет сервера | VPS с Docker (см. operations.md) или облако |
| P3 | Нет SMTP | Креды провайдера почты |
| P4 | Ручная проверка в Claude, ChatGPT и Claude Code | Публичный https-адрес (после P1–P3) |
| P5 | Deep-link параметры GrabFood не подтверждены | Подтверждение от Grab; до этого используется только общая ссылка |

## План следующей версии (по приоритету)

1. **Публикация Demo и Handoff на отдельном хосте**, ручная проверка в Claude.ai, Claude Code и ChatGPT Developer mode; обновить `clients.md` статусами «проверено».
2. **Обращение в Grab** (B1–B5) и параллельно встреча с командой Partner Apps: мини-приложение внутри Grab может дать вход и оплату без консьюмерского API.
3. **Повторное подтверждение для крупных сумм** (passkey / WebAuthn) на страницах подтверждения - до включения Live.
4. **Live-адаптер** за feature-флагами по каждой возможности. Контрактные тесты по документации Grab, прогон в их sandbox (staging-окружение есть у GrabFood POS API и GrabExpress).
5. **MCP URL-mode elicitation** (спецификация 2025-11-25 / 2026-07-28): клиенты с поддержкой смогут открывать страницу подтверждения сами. Страница Unyly остаётся единственным источником согласия.
6. **Переход на ревизию MCP 2026-07-28**, когда официальный SDK её поддержит (сервер уже stateless, состояние в серверных handle).
7. **Дымовой тест подписки** (см. product.md) и дашборд метрик.
8. **Направление GrabExpress**: сценарий «отправь посылку/забери заказ» через документированный Delivery API (sandbox доступен). Это отдельный продукт и отдельные права.
9. Масштабирование: общий rate-limit (Redis или Cloudflare), managed Postgres, реплики приложения (сервер stateless).
