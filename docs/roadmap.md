# Блокеры реального запуска и план следующей версии

## Блокеры

### Для реальных заказов Grab (Live)
| # | Блокер | Кто снимает | Что нужно |
|---|---|---|---|
| B1 | Нет API для заказа Food и Mart от имени покупателя (поиск, меню, цена, создание заказа) | Grab (BD / partnerships) | Партнёрское соглашение и документация consumer-ordering или affiliate API |
| B1a | Нет API бронирования поездок для третьих сторон | Grab (Transport) | Партнёрский ride booking API: тарифы, бронирование, статус, отмена |
| B1b | Нет ключей GrabExpress Delivery API | Отдел продаж Grab | Бизнес-аккаунт, sandbox-ключи, затем production в TH. Самый короткий путь к первому Live-сервису (`express`) |
| B2 | Нет scope GrabID для заказов и оплаты от имени пользователя | Команда GrabID | Список scopes, регистрация redirect URI, условия |
| B3 | Нет схемы оплаты заказа (GrabPay в контексте Food, Mart и поездок) | Grab | Модель оплаты: оплата в Grab с редиректом или токенизация |
| B4 | Нет документированной подписи webhook и статусов потребительского заказа | Grab | Спецификация событий и схема подписи |
| B5 | Нет гарантий идемпотентности создания заказа | Grab | Поле idempotency key или поиск заказа по нашему ключу. Без этого нельзя безопасно сверять неизвестные исходы |
| B6 | Юридическое: PDPA Таиланда, оферта, ответственность за заказ, возвраты | Юрист | Политика данных, оферта, DPA с Grab |

Черновик обращения к Grab - `grab-partner-request.md` (**не отправлен**).

## План следующей версии (по приоритету)

1. **Ручная проверка** ассистентов из `/connect` и Claude Code; обновить `clients.md` статусами «проверено».
2. **Обращение в Grab** (B1–B5, включая ride booking API и ключи GrabExpress) и параллельно встреча с командой Partner Apps: мини-приложение внутри Grab может дать вход и оплату без консьюмерского API.
3. ~~**Повторное подтверждение для крупных сумм** (passkey / WebAuthn) на страницах подтверждения - до включения Live.~~ **Сделано.** Порог по валюте (`STEP_UP_THRESHOLD_<CUR>`, по умолчанию около 2 000 THB / 55 USD, `STEP_UP=off` выключает); для пользователей с passkey кнопка «Подтвердить» запрашивает подпись, привязанную к этому подтверждению (2 минуты, одноразово). Без passkey поток прежний, с рекомендацией добавить ключ. См. threat-model.md, T22.
4. **Live-адаптер** за feature-флагами по каждой возможности. Контрактные тесты по документации Grab, прогон в их sandbox (staging-окружение есть у GrabFood POS API и GrabExpress).
5. **MCP URL-mode elicitation** (спецификация 2025-11-25 / 2026-07-28): клиенты с поддержкой смогут открывать страницу подтверждения сами. Страница Unyly остаётся единственным источником согласия.
6. **Переход на ревизию MCP 2026-07-28**, когда официальный SDK её поддержит (сервер уже stateless, состояние в серверных handle).
7. **Дымовой тест подписки** (см. product.md) и дашборд метрик.
8. **GrabExpress как первый Live-сервис**: сервис `express` уже работает в Demo тем же путём (оценка → корзина → подтверждение → статус). После получения ключей бизнес-аккаунта (B1b) - Live-адаптер за флагом и прогон в sandbox.
9. Масштабирование: общий rate-limit (Redis или Cloudflare), managed Postgres, реплики приложения (сервер stateless).
