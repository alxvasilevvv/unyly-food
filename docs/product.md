# Unyly: краткое продуктовое описание

**Что это.** Unyly - удалённый MCP-сервер с веб-кабинетом. Через него ИИ-ассистент (ChatGPT, Claude и любой MCP-совместимый клиент) помогает заказать еду: подбирает варианты под бюджет, число людей и ограничения, собирает корзину, показывает полную стоимость и готовит заказ. **Подтверждает заказ всегда человек** - на странице Unyly после входа.

**Для кого.** Люди, которые уже общаются с ассистентом и хотят решить задачу «ужин на двоих до 600 бат без орехов» одним сообщением, а не листать приложение.

**Что работает сейчас.**
- **Demo.** Полный сценарий: поиск → меню и модификаторы → корзина → расчёт с раздельными сборами → подтверждение → отправка → статус → отмена. Используются вымышленные рестораны Бангкока, реальных списаний нет.
- **Handoff.** Ассистент собирает список блюд, Unyly даёт официальную ссылку GrabFood Таиланда и чек-лист для ручного оформления. Заказ и оплата происходят в Grab.
- **Live.** Недоступно. У Grab нет публичного API для заказов от имени покупателя (подробнее в `feasibility.md`).

**Бренд.** Самостоятельный бренд Unyly, без имитации Grab и без заявлений о партнёрстве. Акцентный цвет - фиолетовый (не зелёный Grab).

## Основной сценарий

1. Пользователь входит на сайт по коду из письма, выбирает регион и режим, добавляет адрес и указывает предпочтения. Аллергии и диета хранятся **отдельно**.
2. Подключает ассистента: добавляет URL, входит в Unyly и выбирает разрешения.
3. Пишет: «Найди ужин на двоих до 600 бат с доставкой домой. Без орехов. Покажи три варианта».
4. Ассистент вызывает `search_restaurants` и получает для каждого ресторана готовый вариант с оценкой итога, пометкой «в бюджете» и проверкой аллергенов (`none_declared` / `unknown`, никогда «безопасно»).
5. После выбора: `create_cart` → `quote_cart` (товары, доставка, сервисный сбор, доплата за малый заказ, скидка, итог, срок действия) → `prepare_checkout` → ссылка на подтверждение.
6. Пользователь открывает страницу и видит ресторан, состав, модификаторы, адрес, все суммы, способ оплаты, условия отмены и срок действия. Нажимает «Подтвердить и оформить».
7. Ассистент сообщает результат (`get_checkout_status`) и статус (`get_order_status`).

## Гипотеза монетизации

**Гипотеза:** пользователи, которые заказывают еду через ассистента хотя бы раз в неделю, готовы платить небольшую фиксированную подписку за «ассистент-заказчик»: сохранённые предпочтения, повтор заказов одной фразой, поиск под бюджет и ограничения. Оплата сервиса Unyly полностью отделена от оплаты еды в Grab.

**Как проверить без платёжной системы в MVP:**
1. В кабинете разместить «дымовую» кнопку «Unyly Plus - 99 ฿/мес» (цена условная) с формой «сообщить о запуске». Денег не принимать.
2. Метрика: доля активных пользователей (≥ 2 подтверждённых заказа за 14 дней), нажавших кнопку и оставивших email. Порог продолжения: ≥ 8–10% активных.
3. Параллельно - 10 интервью с активными пользователями о ценности и цене.
4. Приём платежей подключать только после выхода в Live и положительного результата теста.

Альтернативу (партнёрская комиссия от Grab) можно проверить только после договора с Grab, поэтому она вынесена в `grab-partner-request.md`.

## Продуктовые метрики

Demo, Handoff и Live считаются **раздельно**. SQL-запросы - в `metrics.sql`.

| Метрика | Источник |
|---|---|
| Успешное подключение ассистента | `audit_log: mcp.connected` |
| Первый подготовленный заказ | первый `checkout.prepared` на пользователя и режим |
| Доля завершённых подтверждений | `checkout.approved` / `checkout.prepared` |
| Подтверждённые провайдером заказы | `orders` |
| Повторное использование | пользователи с заказами в ≥ 2 разных днях |
| Ошибки отправки | `submission_attempts` по `status` и `error_code`, включая `unknown` |
| Handoff | число выданных списков. Завершение в Grab Unyly не видит, и это указывается явно |

## Сознательно не входит в MVP

Регулярные автоматические покупки, объединение нескольких ресторанов в одну транзакцию, замены товаров без согласования, приём платежей за подписку, GrabMart, поездки, GrabExpress.
