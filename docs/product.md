# Unyly: краткое продуктовое описание

**Что это.** Unyly for Grab - удалённый MCP-сервер с веб-кабинетом. Через него ИИ-ассистент (ChatGPT, Claude, Gemini и любой MCP-совместимый клиент) помогает пользоваться сервисами Grab: заказать еду, продукты, цветы, товары аптечки или торт, вызвать машину, отправить посылку. Ассистент подбирает варианты под бюджет, число людей и ограничения, собирает корзину или поездку, показывает полную стоимость и готовит заказ. **Подтверждает заказ всегда человек** - на странице Unyly после входа.

**Для кого.** Люди, которые уже общаются с ассистентом и хотят решить задачу одним сообщением, а не листать приложение: «ужин на двоих до 600 бат без орехов», «12 роз с открыткой», «такси от Siam Paragon в Суварнабхуми», «отправь посылку 3 кг до ICONSIAM».

**Сервисы.**
| Сервис | Что входит | Особенности Demo |
|---|---|---|
| Food | рестораны | модификаторы, аллергены по декларации ресторана, промо, малый заказ |
| Mart | супермаркет, магазин у дома, цветы, аптека, торты | цветы: обязательная обёртка, текст открытки в заметке; аптека: только средства домашней аптечки (ยาสามัญประจำบ้าน), без рецептурных, с лимитом на заказ; торты: надпись в заметке |
| Ride | GrabBike, JustGrab, GrabTaxi, GrabCar Premium, GrabCar SUV, GrabVan | тариф по формуле (посадка + км + минуты), 50 THB за посадку в аэропорту, учёт числа пассажиров |
| Express | посылки на Bike, Car, SUV, Pickup | вес обязателен, лимит веса у каждой машины (20 / 100 / 200 / 300 кг) |

Места для поездок и посылок ассистент передаёт словами на любом из десяти языков: ориентиры, районы или названия сохранённых адресов («Дом»). Если сказано просто «аэропорт», сервер просит уточнить, какой.

**Что работает сейчас.**
- **Demo.** Полный сценарий для всех сервисов: поиск или оценка поездки → корзина → расчёт с раздельными сборами → подтверждение → отправка → статус со своими формулировками для каждого сервиса → отмена. Используются вымышленные магазины, тарифы и места Бангкока, реальных списаний нет.
- **Handoff.** Ассистент собирает список товаров или маршрут, Unyly даёт официальную ссылку Grab на нужный сервис и чек-лист для ручного оформления. Работает во всех 8 рынках Grab: ссылки Таиланда проверены, для остальных открывается `grab.com/{cc}/` с пометкой «не проверено». Заказ и оплата происходят в Grab.
- **Live.** Недоступно. У Grab нет публичного API, через который третья сторона заказывает еду или товары или вызывает машину от имени покупателя (подробнее в `feasibility.md`). Первым кандидатом на Live остаётся GrabExpress: его Delivery API есть для бизнес-аккаунтов.

**Бренд.** Самостоятельный бренд Unyly, без имитации Grab и без заявлений о партнёрстве. Акцентный цвет - фиолетовый (не зелёный Grab).

## Витрина (30.09.2026)

Для показа Grab сайт оформлен как концепт «Unyly for Grab» на десяти языках (EN, TH, VI, ID, MS, FIL, KM, MY, ZH, RU). Главная точка входа - `/try`: человек без регистрации пишет запрос про любой сервис, демо само определяет сервис (еда, продукты, цветы, аптека, торт, поездка, посылка), показывает, какие вызовы MCP сделал бы ассистент, даёт выбрать вариант, подтвердить и посмотреть живой статус. `/connect` - как подключить 10 популярных ассистентов. `/for-grab` - одностраничное предложение для партнёрской команды. Официальная айдентика Grab не используется до согласования.

## Основной сценарий

1. Пользователь входит на сайт по коду из письма, выбирает регион и режим, добавляет адрес и указывает предпочтения. Аллергии и диета хранятся **отдельно**.
2. Подключает ассистента: добавляет URL, входит в Unyly и выбирает разрешения.
3. Пишет: «Найди ужин на двоих до 600 бат с доставкой домой. Без орехов. Покажи три варианта».
4. Ассистент вызывает `search_stores` и получает для каждого ресторана готовый вариант с оценкой итога, пометкой «в бюджете» и проверкой аллергенов (`none_declared` / `unknown`, никогда «безопасно»). Для поездки или посылки вместо этого `estimate_trip` возвращает варианты машин с оценкой цены.
5. После выбора: `create_cart` → `quote_cart` (товары или тариф, доставка, сервисный сбор, доплата за малый заказ, скидка, итог, срок действия) → `prepare_checkout` → ссылка на подтверждение.
6. Пользователь открывает страницу и видит магазин или маршрут, состав, модификаторы, адрес, все суммы, способ оплаты, условия отмены и срок действия. Нажимает «Подтвердить и оформить».
7. Ассистент сообщает результат (`get_checkout_status`) и статус (`get_order_status`).

## Гипотеза монетизации

**Гипотеза:** пользователи, которые пользуются Grab через ассистента хотя бы раз в неделю, готовы платить небольшую фиксированную подписку за «ассистент-заказчик»: сохранённые предпочтения, повтор заказов одной фразой, поиск под бюджет и ограничения. Оплата сервиса Unyly полностью отделена от оплаты заказов в Grab.

**Как проверить без платёжной системы в MVP:**
1. В кабинете разместить «дымовую» кнопку «Unyly Plus - 99 ฿/мес» (цена условная) с формой «сообщить о запуске». Денег не принимать.
2. Метрика: доля активных пользователей (≥ 2 подтверждённых заказа за 14 дней), нажавших кнопку и оставивших email. Порог продолжения: ≥ 8–10% активных.
3. Параллельно - 10 интервью с активными пользователями о ценности и цене.
4. Приём платежей подключать только после выхода в Live и положительного результата теста.

Альтернативу (партнёрская комиссия от Grab) можно проверить только после договора с Grab, поэтому она вынесена в `grab-partner-request.md`.

## Продуктовые метрики

Demo, Handoff и Live считаются **раздельно**. SQL-запросы - в `metrics.sql`.

| Метрика | Источник |
|---|---|
| Успешное подключение ассистента | `audit_log: mcp.connected` |
| Первый подготовленный заказ | первый `checkout.prepared` на пользователя и режим |
| Доля завершённых подтверждений | `checkout.approved` / `checkout.prepared` |
| Подтверждённые провайдером заказы | `orders` |
| Повторное использование | пользователи с заказами в ≥ 2 разных днях |
| Заказы по сервисам | `orders.service` (food, mart, ride, express) |
| Ошибки отправки | `submission_attempts` по `status` и `error_code`, включая `unknown` |
| Handoff | число выданных списков. Завершение в Grab Unyly не видит, и это указывается явно |

## Сознательно не входит в MVP

Регулярные автоматические покупки, объединение нескольких магазинов или поездок в одну транзакцию, замены товаров без согласования, рецептурные лекарства, поездки с несколькими остановками, приём платежей за подписку.
