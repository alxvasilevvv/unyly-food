# Модель угроз

Активы: деньги пользователя (в Live), его согласие на заказ, адреса и email, токены ИИ-клиентов, целостность заказов.
Действующие лица: пользователь; ИИ-модель (может ошибаться или поддаться инъекции); ИИ-клиент (приложение); злоумышленник в сети или с чужим аккаунтом; скомпрометированный провайдер, ресторан или магазин (недоверенный контент).

| # | Угроза | Мера | Где | Проверено тестом |
|---|---|---|---|---|
| T1 | Модель оформляет заказ без согласия человека (галлюцинация, «пользователь согласен», `confirmed=true`) | Согласие существует только как `checkouts.status='approved'`. Выставить его можно одним способом: POST со страницы Unyly с cookie-сессией и CSRF-токеном. У MCP нет инструмента одобрения, лишние аргументы отклоняются схемой | `services/checkout.ts`, `web/routes.ts` | safety: «submit_order without human confirmation…» |
| T2 | Prompt injection через меню, описание товара или заметки магазина | Текст меню отдаётся в поле `description_untrusted` с пометкой. Инструкции сервера запрещают ему следовать. Путь обхода подтверждения отсутствует (T1) | `mcp/tools.ts`, `catalog.ts` | safety: «menu text that tries to instruct…» |
| T3 | Человек подтвердил одно, а отправлено другое (цена, состав, адрес или маршрут поменялись) | Подтверждение привязано к версии корзины, отпечатку адреса (для поездки и посылки: отпечатку маршрута плюс содержимому сохранённых адресов в его точках), quote, сумме, валюте и TTL; перед отправкой всё проверяется заново. Форма передаёт сумму, которую видел человек, и расхождение отклоняется. Провайдер сверяет `expected_total` | `checkout.ts`, `carts.ts` (`locationFingerprint`), demo-provider | safety: «Invalidation of confirmations» (6 тестов); services: «full ride flow…», «editing a saved address used by a trip…» |
| T4 | Двойной заказ: повтор, двойной клик, гонка, рестарт, таймаут, новое подтверждение после неизвестного исхода | Блокировка корзины и checkout; по корзине нет новых отправок, пока есть `in_flight`/`unknown`/`accepted`; `UNIQUE(checkout_id)`, idempotency key у провайдера, сверка вместо повтора, `SUBMISSION_UNKNOWN` | `checkout.ts`, `jobs/worker.ts` | safety: «Duplicate protection»; resilience: весь файл |
| T5 | Доступ к чужим объектам (IDOR) и перебор ID | `user_id` берётся только из токена или сессии, каждый запрос фильтрует `WHERE user_id=$`. Чужой объект возвращает NOT_FOUND. ID - UUIDv4, rate limit | services, routes | access: «Object ownership» |
| T6 | Кража или повторное использование токена | Непрозрачные токены хранятся как SHA-256, access живёт 1 час. Refresh ротируется, повторное использование отзывает весь grant. Повтор кода авторизации тоже отзывает grant. Отзыв доступен в кабинете | `auth/oauth.ts` | access: «refresh token rotation», «PKCE…code reuse», «revoking access» |
| T7 | Токен другого ресурса (confused deputy / passthrough) | Проверяется audience: `grant.resource` должен совпадать с `MCP_RESOURCE_URL`. Токен Unyly никогда не передаётся в Grab | `verifyAccessToken` | access: «audience check» |
| T8 | Перехват кода авторизации | PKCE только S256; точное совпадение `redirect_uri` (для http-loopback допускается любой порт по RFC 8252, хост, путь и query совпадают точно); https или loopback; параметр `iss` в ответе (RFC 9207) | `oauth.ts` | access; compat: «loopback redirect URIs…» |
| T9 | Открытый редирект | При недоверенном `client_id` или `redirect_uri` ошибка показывается на нашей странице без редиректа. `next` после логина допускает только относительный путь | `parseAuthzRequest`, `safeNext` | access: «never redirects…» |
| T10 | CSRF на страницах подтверждения и отмены | Токен сессии в каждой форме, проверка Origin/Referer, SameSite=Lax, `Referrer-Policy: same-origin` | `auth/session.ts` | safety: «web confirmation requires CSRF» |
| T11 | Clickjacking страницы подтверждения | `frame-ancestors 'none'` | helmet CSP | demo-flow (заголовок) |
| T12 | SSRF через Client ID Metadata Document | Только https на порту 443. DNS проверяется, приватные и loopback-диапазоны блокируются, IP закрепляется на время запроса. Без редиректов, 5 с, 16 КБ | `fetchClientMetadata` | access: «SSRF protection» |
| T13 | Подделка webhook, повтор, неверный порядок | HMAC и окно ±300 с; `UNIQUE(event_id)`; применение по `sequence`; терминальные статусы необратимы | `orders.ts` | resilience: «Webhooks» |
| T14 | Утечка PII в ответы MCP и логи | Ассистент получает только название адреса и район. Логи маскируют `authorization` и `cookie`. Email в логах почты замаскирован. Экспорт и удаление в кабинете | `users.ts`, `app.ts` | access: «export and deletion» |
| T15 | Подмена демо-данными при сбое Live | Провайдер выбирается по `cart.mode` или `user.mode`, fallback отсутствует. Ошибка - `PROVIDER_UNAVAILABLE`, а статус заказа отдаётся из БД с пометкой | `common.ts`, `orders.ts` | resilience: «no demo substitution» |
| T16 | Сбор паролей, OTP и карт Grab | Интерфейс и инструменты их не принимают; в документации и на главной это сказано явно | - | - |
| T17 | Перебор кодов входа | 6 цифр, 5 попыток на код (счётчик фиксируется до ответа), 5 кодов в час на email, rate limit по IP | `session.ts` | regressions: «login code attempts…» |
| T18 | Опасные советы по аллергии | Аллергии хранятся отдельно от диеты. Используются только декларации ресторана, статус `unknown` при отсутствии данных. Формулировок «безопасно» нет | `catalog.ts` | demo-flow: search |
| T19 | Массовые заказы при ошибке | Выключатель новых заказов по режиму (env + БД); чтение статусов при этом работает | `common.ts` | safety: «Kill switch» |
| T20 | Кража персонального токена | Префикс `unyly_pat_`, хранится только SHA-256, показывается один раз, ограниченные scopes и срок (до 365 дней), не больше 10 активных, отзыв в кабинете. Только заголовок `Authorization`, токен в URL отклоняется (не попадает в логи прокси). Гости токены не создают. Подтверждение заказа токеном не обходится (T1) | `oauth.ts`, `web/routes.ts` | compat: «Personal tokens…» |
| T21 | Опасные советы по лекарствам | В аптеке демо только средства домашней аптечки, рецептурных нет; лимит `max_quantity` на заказ считается по всем строкам; инструкции сервера запрещают ассистенту предлагать рецептурные препараты и дозировки сверх этикетки | `catalog.ts`, `carts.ts`, `mcp/tools.ts` | services: «per-order limits…» |

## Остаточные риски

- **Скомпрометирована почта пользователя** - злоумышленник войдёт и подтвердит заказ.
- **Персональный токен живёт дольше OAuth-токена** (до 365 дней, без ротации). Утечка даёт доступ к подготовке и, при scope `orders:submit`, к отправке уже подтверждённых человеком заказов, но не к подтверждению. Для Live стоит добавить повторное подтверждение (passkey / WebAuthn) на страницы подтверждения при сумме выше порога.
- **Спецификация MCP считает аннотации недоверенными.** Если клиент их не учитывает, модель может вызвать `submit_order` без вопроса. Это безопасно: без одобрения на сайте вызов вернёт `CONFIRMATION_REQUIRED`.
- **DNS rebinding для CIMD** закрыт закреплением IP. Изменение цели после резолва (TOCTOU) не играет роли, потому что соединение идёт на проверенный IP.
- **Секреты** лежат в `.env` на хосте. Для production нужен менеджер секретов (Doppler, 1Password Connect, AWS/GCP Secret Manager); см. operations.md.
- **Юридическое** (PDPA Таиланда, оферта, возвраты) до запуска Live требует проверки юристом.
