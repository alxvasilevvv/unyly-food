# Отчёт о реализуемости интеграции с Grab

Дата проверки: **30.09.2026**. Все выводы ниже опираются только на официальные источники. Если документацию не удалось открыть, пункт помечен как «не проверено».

## Вывод

1. **Live-заказы от имени покупателя сейчас нереализуемы ни для одного сервиса.** Grab не публикует API, через который третья сторона могла бы искать рестораны или магазины, рассчитывать корзину, оформлять и оплачивать заказ GrabFood или GrabMart за покупателя, или бронировать для него поездку. Публичные API Food и Mart устроены для мерчантов и POS-систем: магазин синхронизирует своё меню или каталог и получает свои заказы. Публичного API бронирования поездок для третьих сторон в документации нет.
2. **Авторизация от имени пользователя Grab (GrabID / Login with Grab) существует, но scopes выдаются только при ручном онбординге партнёра.** Публично описан один scope, `openid`. Scope для заказов, покупок или поездок от имени пользователя не документирован.
3. **Пользовательские условия Grab запрещают ботов, скрипты и скрейпинг.** Поэтому автоматизация приложения, cookies и приватные API исключены.
4. **Доступный сейчас путь - Handoff.** Это официальные веб-страницы сервисов Grab без параметров корзины, магазина или маршрута, плюс Demo для полного сценария. В Таиланде проверены страницы Food, Mart, Transport и Express; для остальных 7 рынков используется `grab.com/{cc}/`, и ссылка помечена как непроверенная.
5. **Первый кандидат на Live - GrabExpress Delivery API.** Он документирован, есть sandbox, работает для бизнес-аккаунтов (ключи выдаёт Grab через отдел продаж). Это отправка посылок от имени бизнеса, поэтому сервис `express` можно было бы включить первым, если Unyly получит бизнес-аккаунт.

**Страна запуска:** Таиланд. Это **предварительное продуктовое допущение**, а не результат проверки доступа: реального доступа к Grab нет ни в одной стране. Выбор опирается на два факта: GrabFood работает в TH (GrabFood POS API, раздел Available regions), а у THB exponent = 2 (там же, раздел о валютах). Demo-данные есть только для Бангкока; выбор рынка в кабинете открыт для всех 8 стран Grab (TH, SG, MY, ID, VN, PH, KH, MM), и в них работает только Handoff.

## MCP и клиенты (кратко, подробности в `clients.md`)

- Последняя версия спецификации MCP - **2026-07-28**: stateless-протокол, без `initialize` и `Mcp-Session-Id`. Официальные TypeScript SDK (`@modelcontextprotocol/sdk` 1.31.0 от 28.09.2026 и `@modelcontextprotocol/server` 2.2.0) реализуют протокол до **2025-11-25** включительно.
- Выбор: SDK 1.31 + Streamable HTTP в stateless-режиме. Состояние корзины хранится в серверных идентификаторах (`cart_id`, `checkout_id`), как и рекомендует 2026-07-28. Поэтому переход на новую ревизию сводится к обновлению SDK.
- Авторизация: OAuth 2.1 + PKCE S256, RFC 9728 (Protected Resource Metadata), RFC 8707 (`resource` и проверка audience), RFC 8414, Client ID Metadata Documents (SHOULD) и Dynamic Client Registration (MAY, deprecated, оставлена для совместимости). Для совместимости с клиентами: scope `offline_access` принимается, loopback redirect на любом порту (RFC 8252), а для клиентов без OAuth есть персональные токены.

## Что это значит для продукта

| Режим | Статус | Что делает |
|---|---|---|
| Demo | **Работает** | Полный сценарий для food, mart, ride и express на синтетических данных Бангкока, без списаний |
| Handoff | **Работает** | Список товаров или маршрут и официальная ссылка Grab на сервис во всех 8 рынках (проверены только ссылки TH). Заказ, оплата и статус - внутри Grab |
| Live | **Выключен** | Все возможности возвращают `CAPABILITY_UNAVAILABLE` с причиной и источником |

Черновик обращения к Grab лежит в `grab-partner-request.md`. Он не отправлялся.
